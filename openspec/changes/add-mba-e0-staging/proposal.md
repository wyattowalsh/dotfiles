## Why

The accepted MBA migration needs a real additive music transfer. The existing staging command only plans, and the one-file capacity evaluator cannot represent an honest historical pre-E0 observation after a long transfer.

## What Changes

- Add an explicit E0-only production path to the existing staging CLI, pulling from the named source over strict SSH into a new private target root.
- Reuse the existing census, journal, full-file hashes, exclusive rename and APFS observer; preserve the disposable fixture APIs and default read-only plan.
- Resume verified good files without replacement; retain failed partials and interrupted journal history. Keep journal/control state outside the unserved media tree.
- Add an optional v3 pre-E0 start anchor while keeping post-E0 observations fresh, existing unanchored behavior and v2 unchanged.
- Document the private operator contract and separate source fixtures from live acceptance.
- Permit an explicit frozen whole-census limit up to 100,000 entries/240MB after a measured library exceeds the 10,000 default; propagate the same bound through both hosts without partial-batch acceptance.
- Preserve existing supported original formats and literal filenames, resolve album playlists within the observed root, and copy retained companions without claiming they are playable or phone-eligible.
- Protect the paired Macs from legacy music/Navidrome service reapply using existing Chezmoi target ignores and native install guards; retain Pueue without Brew service restart and keep MBA activation owned by its existing private contract installer.
- Add one explicitly installed normal-user MBA AC-only awake LaunchAgent, with native assertion/PID readback; preserve display sleep, battery behavior and MBP power settings.
- Correct likes format presence using exact beets bitrate and bounded codec headers; preserve the existing version-specific queue, KEEP policy and no automatic deployment or companion invention.
- Admit an optional explicit operator-reviewed companion-edition CSV to the existing likes queue, retaining distinct extended/radio target metadata and both requested formats; report unresolved declarations without inventing editions, changing Spotify exports or acquiring media.

## Capabilities

### New Capabilities

- `mba-e0-staging`: serial, non-deleting, recoverable E0 staging and historical pre-E0 capacity anchoring.

### Modified Capabilities

None.

## Impact

The existing staging/capacity scripts, focused tests and music operator runbook are joined by narrowly scoped Chezmoi ignores, legacy music installer guards, the existing Pueue service flag and a separate MBA AC-only user LaunchAgent. No generic role framework, automatic live apply, goal-graph rewrite, root daemon, new dependency, media copy, installed service retirement or E1 publication is introduced. Retained plists support deliberate manual rollback; the legacy installer is blocked on the paired identities. The awake source requires its own exact named-host install and native assertion readback, not a wholesale rig apply.

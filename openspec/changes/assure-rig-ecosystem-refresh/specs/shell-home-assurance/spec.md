## ADDED Requirements

### Requirement: Process selection cannot target special PIDs

The interactive `fkill` helper SHALL pass only unique, valid user-process identifiers to `kill` and SHALL preserve cancellation and command-failure semantics.

#### Scenario: Candidate is unsafe or malformed

- **WHEN** a selection contains PID 0, PID 1, the current shell PID, nondigits, an empty token, or a value greater than 2,147,483,647
- **THEN** that candidate is excluded before `kill` is invoked

#### Scenario: Candidate is duplicated

- **WHEN** a valid PID appears more than once in selected rows
- **THEN** it is passed to `kill` exactly once

#### Scenario: Selection is cancelled

- **WHEN** fzf exits without a selection
- **THEN** the helper returns without invoking `kill`

#### Scenario: Kill fails

- **WHEN** `kill` rejects a selected valid PID
- **THEN** the helper returns a nonzero status rather than masking the error

### Requirement: pnpm completion is reproducible desired state

The managed zsh completion directory SHALL contain a tracked `_pnpm` completion generated by the repository's current pinned pnpm toolchain.

#### Scenario: Completion is loaded

- **WHEN** zsh initializes completion
- **THEN** the managed completion directory is present in `fpath` before completion initialization
- **AND** `_pnpm` is discoverable without generating a live untracked file

#### Scenario: Completion is verified

- **WHEN** the completion reproducibility check runs with the pinned pnpm version
- **THEN** regenerated output matches the tracked `_pnpm` artifact

### Requirement: uv synchronization is explicit

Routine direnv evaluation SHALL not perform package synchronization or network-capable environment mutation.

#### Scenario: Existing uv environment

- **WHEN** `layout_uv` is invoked and the expected environment already exists
- **THEN** it activates that environment without running `uv sync`

#### Scenario: Missing uv environment

- **WHEN** `layout_uv` is invoked without the expected environment
- **THEN** it returns an actionable error naming `layout_uv_sync`
- **AND** it does not create or synchronize an environment

#### Scenario: Explicit synchronization

- **WHEN** the operator invokes `layout_uv_sync`
- **THEN** it runs `uv sync --frozen`
- **AND** it activates the resulting environment only after synchronization succeeds

### Requirement: Shell plugin contracts remain bounded and ordered

The shell SHALL retain exactly twelve Oh My Zsh plugins, load `zsh-you-should-use` only from Homebrew after aliases, and load syntax highlighting last.

#### Scenario: Plugin and history check

- **WHEN** shell structure checks run
- **THEN** the exact approved twelve-plugin set is present
- **AND** `HISTSIZE` remains greater than `SAVEHIST`
- **AND** the approved history options remain enabled

#### Scenario: Homebrew helper ordering

- **WHEN** `.zshrc` is evaluated
- **THEN** aliases load before the Homebrew `zsh-you-should-use` script
- **AND** no `ZSH_CUSTOM` fallback is used
- **AND** syntax highlighting loads after all other interactive plugins

### Requirement: Yazi dependencies and appearance are locked

Every plugin or flavor referenced by tracked Yazi configuration SHALL be represented by a resolved lock in `package.toml`.

#### Scenario: Plugin locks

- **WHEN** Yazi configuration invokes `git`, `toggle-pane`, or `piper`
- **THEN** `package.toml` contains resolved `yazi-rs/plugins` locks for all three

#### Scenario: Light and dark flavors

- **WHEN** Yazi chooses a dark or light appearance
- **THEN** dark mode resolves to locked `Mintass/rose-pine`
- **AND** light mode resolves to locked `Mintass/rose-pine-dawn`

#### Scenario: Configuration parses

- **WHEN** the tracked Yazi configuration is loaded under the supported Yazi version in a temporary config home
- **THEN** current `[mgr]`, `url`, `group`, plugin, and flavor fields parse successfully

### Requirement: Yazi custom keys preserve built-in navigation

DuckDB horizontal navigation SHALL use Option-modified keys without shadowing Yazi's Go Home or directory-history bindings.

#### Scenario: DuckDB navigation is configured

- **WHEN** the Yazi keymap is loaded
- **THEN** DuckDB previous and next actions use `<A-h>` and `<A-l>`

#### Scenario: Preset navigation remains available

- **WHEN** the tracked keymap is inspected
- **THEN** it does not override `g h`, `H`, or `L`

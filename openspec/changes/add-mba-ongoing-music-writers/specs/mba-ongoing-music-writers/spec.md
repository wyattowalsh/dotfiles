## ADDED Requirements

### Requirement: One serialized music publication transaction
An ongoing writer SHALL retain the existing music-writer file description through reader exclusion, file writes, full census, immutable epoch publication and deliberate reader activation. The guarded reader's real exclusive lease SHALL cover the write window. Its normal anchored cleanup SHALL complete before writing; uncertain cleanup or a retained unclean marker SHALL refuse continuation.

#### Scenario: Verified new import
- **WHEN** the existing importer verifies distinct new Beets IDs, new canonical paths, stable source inputs and complete source/destination byte hashes
- **THEN** the transaction retains those exact proofs before the importer clears its success marker
- **AND** the final census contains the unchanged accepted parent plus only those verified files and their required directories
- **AND** an unexplained addition, old-file change, removal or broken ID chain refuses publication and automatic restart

### Requirement: Preserve the existing Liked Songs playlist
The existing version-aware matcher and format preference SHALL generate the single canonical `Playlists/Liked Songs.m3u` in Spotify order using the effective recovered database and existing export. A declared companion transformation SHALL bind its exact prior row or absence, generated bytes and input references. It SHALL permit changes to no other accepted file. Playlist-only publication SHALL require an actual changed companion, while import proofs remain mandatory for new imported audio.

#### Scenario: Playlist refresh
- **WHEN** the generated playlist differs from the accepted canonical playlist
- **THEN** the same stopped-reader transaction replaces only that declared companion and publishes the fresh complete census
- **AND** publication describes the declared transformation without claiming every parent byte was unchanged
- **AND** distinct version metadata and format selection retain the existing matcher's behavior

#### Scenario: No eligible work
- **WHEN** no settled new input exists and the requested playlist already matches
- **THEN** the invocation performs no reader stop, full-library census, epoch allocation or publication
- **AND** the existing writer lock still serializes the readiness check

#### Scenario: A download event is missed or the writer is busy
- **WHEN** a filesystem notification is missed or an ingest invocation cannot acquire the shared writer lock
- **THEN** a periodic ingest reconciliation trigger eventually checks the settled inbox again
- **AND** the existing watch trigger remains enabled and unchanged work follows the cheap no-op path

### Requirement: Durable immutable acceptance and explicit recovery boundaries
Each accepted change SHALL create new immutable publication, census, witness and operator controls. Only the small selected descriptor SHALL advance. Existing controls and recovery references SHALL remain unchanged. A durable pending marker SHALL precede effects; uncertain imports, publication or activation SHALL require reconciliation and SHALL NOT be automatically replayed.

#### Scenario: Accepted publication and activation
- **WHEN** complete byte comparison and declared transformations pass
- **THEN** the transaction releases the reader lease while retaining the writer lease, explicitly rearms the genuine new epoch if required, and starts the exact normal-account reader service
- **AND** acceptance requires an actual activation receipt joined to the operator and service contract
- **AND** supervisor observation alone does not establish native playback, reboot, backup, phone delivery or independent recovery

### Requirement: Deliberate normal-account service ownership
The reader service SHALL use a single normal-user LaunchAgent with `RunAtLoad=true` and `KeepAlive=false`, genuine recovered initial E1 references and the existing native guard. Initial installation SHALL verify source-reader exclusion and retained writer retirement evidence. Later MBA-only publications SHALL consume the retained retirement evidence locally and SHALL NOT require waking the MBP. Writer installation SHALL preserve the existing watch and calendar behavior, credentials and scopes, with explicit bound inputs and an inert preview.

#### Scenario: Installation and later scheduling
- **WHEN** the actual recovered state, effective consumer and one-owner admissions are ready
- **THEN** an explicit installation may select the reviewed services without using the retired legacy installer
- **AND** source checks, staged files and unbound templates cannot activate them
- **AND** future imports reuse the existing organized-phone hook without claiming convergence, playback or recovery from a successful local publication

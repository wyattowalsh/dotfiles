`brew/Brewfile` is **curated desired state**. Raw dumps are evidence only — review `local/Brewfile.raw` from `just inventory-redacted` before promoting entries.

## Validate

```bash
just inventory-redacted   # refresh local/Brewfile.raw
just brew-check           # brew bundle check --file brew/Brewfile
```

## Brewfile groups

| Group | Examples | Notes |

| `quicklook` | `qlmarkdown`, `quicklook-json` | macOS Quick Look plugins |

## Taps

- `just` (formula) — workflow runner (`justfile` recipes)
- `oven-sh/bun` — Bun runtime
- `stripe/stripe-cli` — Stripe CLI
- `supabase/tap` — Supabase CLI

## Services

Some formulae declare `restart_service: true` (e.g. `pueue`). Promote service intent explicitly — default stopped databases and cloud daemons unless deliberately managed.

## Nix complement

Durable system and user packages also live in `darwin/` modules. Prefer nix-darwin for reproducible system state; Homebrew for the broad GUI and cask surface.

## Promotion checklist

1. Classify the package into a Brewfile comment group
2. Decide service start/stop policy
3. Add to `brew/Brewfile`
4. Run `just brew-check`
5. Apply via `just bootstrap --apply`

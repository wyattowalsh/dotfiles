Free personal tailnet plus the ordinary RustDesk macOS client. Direct IP through Tailscale. No RustDesk Server, hbbs/hbbr, Headscale, Funnel, or paid infrastructure. **Automated MBA remote-control enablement is blocked; an installed app is not a working remote session.** The repo source has a safety hold: `enable`, `disable`, and `rollback --apply` exit before acquiring a lock or changing native options, launchd, or plists. A matching on-disk plist does not prove which job is loaded under its label, and a pathname hash cannot make a later removal atomic against a privileged writer. Existing access may still be active after a blocked command. The installed runner is not changed by this source edit; a preexisting `$HOME/.local/bin/remote-access` copy may lack the hold and must not be used as an apply workaround. Separate review, exact approval, and attended macOS/vendor/TCC proof remain required.

```bash
just remote-access                 # plan (read-only)
just remote-access install --dry-run
just remote-access enable --dry-run
just remote-access doctor
just check-remote-access           # static only; sandbox fixtures run under just check-bats
```

`just remote-access*` always runs the **repo source**. Launchd never runs this script. Dest runner `$HOME/.local/bin/remote-access` is a copy for PATH use.

Generic `just bootstrap --apply` and Chezmoi apply **never auto-enable** unattended access. Pass `--with-remote-access` only to install packages; an explicit approved enable remains a separate operation.

## Lifecycle

This host already declared `brew "tailscale"`. The runner **reuses that formula**. It does not install `cask "tailscale-app"` next to it.

| Piece | Owner | Why |
| --- | --- | --- |
| Tailscale | `sudo brew services start tailscale` (current Homebrew label `sh.brew.tailscale`) | Single lifecycle. Formula `tailscaled` can run at LoginWindow after FileVault unlock. Do not also run `tailscaled install-system-daemon`. |
| RustDesk | Vendor `com.carriez.RustDesk_service` (root daemon) + `com.carriez.RustDesk_server` (user agent, LoginWindow + Aqua) | Historical 1.4.9 templates in the source runner, **not** verified for a newer installed app. macOS `--install-service` only **checks** plists; it does not install. |
| This repo | `just remote-access` | Read-only planning and a separately gated installer. Enable/disable/rollback apply remain held in source. No homemade `open`+KeepAlive watchdog or `.zshrc` startup. |

If a GUI Tailscale.app is already present, the runner preserves it and does not start a second daemon. That GUI variant does **not** run before login.

## Deferred setup

These are future operator steps, **not** approval to run them now. `install --apply` needs its own package-state review and authorization; source `enable --apply` cannot succeed while the provenance hold remains. Do not use `disable --apply` as an emergency-off command: it also stops before making changes.

1. `just remote-access` — confirm backend `brew-formula-tailscaled` and that no GUI app is competing.
2. `just remote-access install --apply` — cask `rustdesk` if missing; dest runner; **does not** enable the listener.
3. Log the Mac into the existing personal tailnet: `sudo tailscale up` then `sudo tailscale set --operator=$USER`. Do not pass `--reset`, do not rotate node keys, do not enable SSH / Funnel / Serve / subnet routes / exit nodes.
4. Open RustDesk. Settings → Security: enable **Direct IP access**, set a **unique permanent password** in the app UI, set approval to **password only**. Never put the password in chat, git, logs, or argv.
5. In a later approved pilot, sign the intended controller into the **same** tailnet and bring it online. The MBA migration names the **MBP** controller rather than assuming a default phone. Review the selected Tailscale peer ID and tailnet; a replacement node requires a separate rebind decision.
6. **Do not use** source or older installed `enable --apply --peer <unique-mbp-hostname>` while the hold remains. Disk plist hashes, labels, PIDs and a user-owned lock cannot prove effective loaded-job provenance or exclude privileged/vendor writers. For a newer app, review its actual vendor-supported attended setup and revocation path with the operator before separately approving any GUI action; do not install the historical 1.4.9 plists by assumption. If no supported unattended startup exists, stop at logged-in use rather than claiming reboot recovery. The blocked source command changes nothing and does not revoke an existing session.
7. Grant **Screen Recording**, **Accessibility**, and **Input Monitoring** (RustDesk docs: Input Monitoring is required on newer macOS). The runner opens System Settings when a TTY is present; it never edits TCC.

The historical lifecycle fixture models native-off, persistent launchd disables, bootout and listener readback in an isolated mock root. That fixture is **not** the production source behavior: all three lifecycle apply commands are held before host mutation. Production `doctor` also refuses an enabled-green result based only on a loaded label and matching disk plist. An operator must inspect and reconcile an existing session locally; Tailscale remains separate.

## iPhone

- Tailscale: [App Store](https://apps.apple.com/us/app/tailscale/id1470499037)
- RustDesk: [App Store](https://apps.apple.com/us/app/rustdesk-remote-desktop/id1581225015)

On the phone: join the same tailnet, enable the VPN, put the Mac's Tailscale IPv4 (from `just remote-access doctor` / `tailscale ip -4`) in RustDesk's Remote ID box, then enter the password in the app. Do not use the numeric RustDesk ID for this workflow.

`doctor` is read-only. For **enabled** intent it now returns nonzero: journal, settings, peer, listener and matching on-disk plists cannot prove the effective loaded launchd job's identity. For disabled or rolled-back intent it still checks native-off sentinels, exact-label persistent overrides, launchd absence and all-port listener absence; uncertain inspection is not green. Empty listener output proves no match only with `lsof` exit **1**; empty exit **0** remains **unknown**, not safely off. Nonempty successful output must contain complete, valid PID/command groups; orphan fields, malformed PIDs and incomplete groups are also **unknown**. Privileged readback uses noninteractive sudo (`-n`). It does not print passwords or peer allowlist addresses. Synthetic readback and reboot fixtures are not live named-peer control, vendor startup, TCC or post-login proof; those gates remain open.

## Startup boundaries

| Situation | Tailscale (`tailscaled` formula) | RustDesk vendor agent |
| --- | --- | --- |
| Unlocked Aqua session | Yes, if brew service loaded | Yes (`--server`) |
| Locked session, user still logged in | Yes | Yes, if the agent stayed loaded |
| Logged out (LoginWindow, FileVault already unlocked) | Yes (plist includes LoginWindow/System) | Agent `LimitLoadToSessionType` includes LoginWindow |
| After reboot, before FileVault unlock | **No** | **No** |
| After FileVault unlock, before login | Documented for `tailscaled`; less tested than the GUI | Vendor agent is supposed to load at LoginWindow |

Apple silicon + recent macOS can unlock FileVault over SSH when Remote Login is on. This feature **does not** turn Remote Login on. Do not assume the Mac is reachable before protected storage is available.

macOS 27 beta: treat LoginWindow/pre-login behavior as **unverified** until you test a reboot with an out-of-band recovery path.

## Encryption and exposure

Tailscale encrypts transport, including DERP relay fallback. RustDesk may still label a **direct-IP** session as unencrypted at the RustDesk layer. That label is not a claim about Tailscale. It also does **not** apply to a raw LAN or public-IP listener.

The RustDesk process listens on the configured direct-access port (upstream default **21118**; `doctor` checks the live port). A `100.x` address is not Tailscale authentication by itself. Enable refuses an empty whitelist (`allow-all`). Access control is: tailnet membership + the selected named peer's allowlist (**MBP** for the MBA migration) + the permanent password. Tailscale ACLs are not rewritten.

LAN discovery is turned off when enabling. The stock client may still contact public ID/rendezvous servers. Direct-IP success does not prove those calls stopped. Do not fake custom server endpoints.

## Power

Display sleep is not system sleep. This feature does not change `pmset`. There is no `caffeinate` loop. Closed-lid reachability and Wake-on-LAN over Tailscale are **unclaimed**.

The separate MBA host-availability source is `rig/bootstrap/mba-awake/com.wyattowalsh.mba-awake.plist`: one normal-user Aqua LaunchAgent runs `/usr/bin/caffeinate -s` with `RunAtLoad` and `KeepAlive`. Its explicit installer is restricted to the named MBA account; generic bootstrap/Chezmoi and the MBP are unaffected. Apple's native `caffeinate` manual defines `-s` as a system-sleep assertion valid on AC power. It adds no display-wake flag, all-power idle assertion, root power-setting change or lid-sleep override. Source presence is not installed proof: bind the loaded label's exact PID/UID/argv to its own `PreventSystemSleep` assertion on AC and inspect the native sleep-preventer readback. A zero `PreventUserIdleSystemSleep` count alone does not reject this different assertion type. If AC assertion or idle-prevention evidence is absent, keep that result unproved rather than silently adding `-i` or changing `pmset`. Next-login and attended lock/idle reachability remain separate host acceptance. Explicit disable boots out/disables only this label and retains its plist for rollback.

## Updates

`brew upgrade tailscale` keeps the brew service unit. Re-run `just remote-access doctor` after upgrades. Do not silently replace a working GUI install. RustDesk cask upgrades may require an attended review of vendor plists. Source `enable --apply` is **held** and cannot repair or revoke an existing session. The historical off-first implementation is fixture-only until a separately reviewed provenance design can safely lift that hold.

## Disable / rollback

```bash
just remote-access disable --dry-run
just remote-access rollback --dry-run
just remote-access doctor
```

All three lifecycle `--apply` commands return **4** at the source hold before the state lock, journal read, native-option write, launchd call, or plist removal. This is a refusal, **not** evidence that direct IP or an existing session is off. Do not delete the journal or original backup, clear a lock, or force a rebind to bypass it. An attended local operator must first determine what is actually loaded and whether remote control remains active; any later intervention or lifted hold requires separate review and authorization.

The owner-only journal and SHA-256 claims remain as historical evidence, not proof of a loaded job's origin. A source fixture-only copy exercises the former lifecycle logic against a sandbox and mocked `sudo`/`launchctl`; it cannot authorize production apply. The production source no longer automatically unlinks vendor plists: if a future reviewed lifecycle reaches rollback while a plist exists, it preserves the file and claim and reports **incomplete**, rather than `rolled-back`. Even an identical replacement may belong to another writer. The native-option hash/check-then-replace path has a separate concurrent-writer window, so no source fixture closes live vendor/root-writer, stale-lock, TCC or post-login safety. Tailscale identity, RustDesk.app and the permanent password remain outside automatic rollback.

## Human acceptance

1. From the **named allowed controller**—the MBP for this MBA migration—connect to the MBA's tailnet address and verify actual screen, input and clipboard. For a separately approved iPhone target, repeat on cellular with Wi-Fi off and Tailscale VPN on.
2. Disconnect, lock the Mac, reconnect from the same allowed peer; confirm an unallowlisted peer cannot control it.
3. Test restart/recovery only with separate approval and an attended FileVault unlock path.
4. From an owned LAN device **not** on the tailnet, verify the listener is not a usable unauthenticated path.

A local socket, localhost connect or source fixture is **not** proof of named-peer remote control or post-login recovery.
